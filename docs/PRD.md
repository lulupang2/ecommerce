# TECHZONE 제품 요구사항 문서

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | OMS/WMS v1 구현 기준 |
| 기준일 | 2026-07-24 |
| 제품 | 한국어 테크·IT 커머스 웹/하이브리드 앱과 운영 CMS |
| 목적 | MSA, 이벤트 기반 업무 흐름, 상용형 관리자 운영 역량을 보여주는 포트폴리오 |

## 목표 사용자

- 고객: 상품 탐색, 장바구니, 주문·결제, 주문 상태 확인
- CS: 주문·회원·리뷰·반품 조회와 처리
- 상품 MD: 상품·variant·이미지·스펙·가격·상태 관리
- 물류: 다중창고 재고, 입출고, 이동, 시리얼, 출고·배송 관리
- 재무: 결제·취소·환불·매출 KPI 확인
- 슈퍼관리자: 역할·권한·감사로그와 전체 운영 관리

## 고객 핵심 흐름

1. 회원가입·로그인 후 상품 검색과 상세 확인
2. 장바구니와 배송 정보 입력
3. 주문 생성과 Mock 결제 승인
4. 재고 예약 후 주문 확정
5. 출고·송장·배송 상태 확인
6. 반품 검수와 환불

## 아키텍처 요구사항

- 각 서비스는 독립 PostgreSQL DB를 소유하고 다른 DB를 직접 조회하지 않는다.
- Admin Query는 이벤트 기반 projection으로 KPI와 통합 목록을 제공한다.
- processed event ID로 중복 이벤트를 멱등 처리하고 rebuild 명령을 제공한다.
- 주문·결제·출고 상태를 별도 ENUM으로 관리한다.
- 상품은 variant 기준 SKU·모델·바코드·가격·원가를 가진다.
- 재고는 다중창고 balance와 append-only movement 원장을 사용한다.
- 결제·택배사는 adapter 뒤의 Mock 구현을 기본으로 한다.
- 기존 고객용 상품·주문 API DTO 호환성을 유지한다.

## 비기능 요구사항

- 모바일 360px 이상에서 관리자 드로어와 가로 스크롤 테이블이 동작한다.
- 모든 서비스가 `/health`와 Docker healthcheck를 통과한다.
- 금액은 KRW 정수, 시간 표시는 Asia/Seoul, 세금은 부가세 포함 기준이다.
- 오류·로딩·빈 상태·권한 없음과 mutation 성공·실패 피드백을 제공한다.
- 비밀값은 환경 변수로 주입하고 저장소에 커밋하지 않는다.

## 완료 기준

- 현실적인 상품·variant·2개 창고·주문·배송·반품·공급사·발주 시드가 생성된다.
- 주문→결제→재고예약→출고→배송과 반품→환불 통합 테스트가 통과한다.
- RBAC 허용·차단, projection rebuild, 필터·정렬·페이지네이션, 감사로그를 자동 검증한다.
- KPI와 projection 합계가 원본 운영 데이터와 일치한다.
- Next.js production build, 전체 Docker healthcheck, Capacitor sync, Android debug APK 빌드가 성공한다.
