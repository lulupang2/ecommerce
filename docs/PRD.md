# TECHZONE 제품 요구사항 문서(PRD)

| 항목 | 내용 |
| --- | --- |
| 제품명 | TECHZONE |
| 문서 상태 | MVP v0.2 |
| 제품 유형 | 테크·IT 기기 전문 커머스 웹/하이브리드 앱 |
| 주요 목적 | MSA와 이벤트 기반 주문 처리를 보여주는 웹앱 개발 포트폴리오 |
| 기준일 | 2026-07-23 |

## 1. 제품 목표

TECHZONE은 노트북, 스마트폰, 오디오, 게이밍 기기 등을 탐색하고 주문할 수 있는 한국어 쇼핑몰이다. 고객에게는 익숙하고 명확한 구매 경험을 제공하고, 기술적으로는 서비스 분리, 데이터 소유권, 비동기 주문 Saga, 웹·앱 코드 공유 역량을 증명한다.

## 2. 대상 사용자

- 고객: 상품을 검색·비교하고 장바구니와 주문 내역을 관리한다.
- 운영자: 상품, 재고, 주문 상태를 관리한다.
- 채용 담당자: 실행 가능한 데모와 문서를 통해 설계 판단과 구현 완성도를 확인한다.

## 3. 핵심 사용자 흐름

1. 회원가입 또는 로그인
2. 카테고리·검색을 이용한 상품 탐색
3. 상품 상세 확인과 장바구니 담기
4. 배송 정보 입력과 주문 생성
5. 결제 승인과 재고 예약
6. 주문 확정 및 알림 확인
7. 주문 내역과 상세 상태 조회

## 4. MVP 범위

### 구현 완료

- 한국어 반응형 스토어 홈과 상품 카탈로그
- 상품 검색·카테고리 필터·상품 상세 모달
- 장바구니 수량 변경과 주문서 작성
- 이메일 회원가입·로그인·JWT 발급 API
- Mock 결제, 재고 예약, 주문 확정 이벤트 흐름
- 주문 알림, 미디어 업로드 URL, 검색 프록시
- Docker Compose 기반 10개 Node.js 서비스와 서비스별 PostgreSQL DB
- Next.js 정적 웹 빌드와 Capacitor Android 패키징

### 다음 릴리스

- 실제 결제 Sandbox와 객체 스토리지 연결
- E2E 테스트와 CI/CD, 관측성 대시보드

## 기술 기준

- 프론트엔드: Next.js 16, React 19, Tailwind CSS 4, shadcn/ui 패턴
- 백엔드: NestJS 런타임(Express adapter), Node.js 22
- ORM: Drizzle ORM 및 Drizzle Kit
- 데이터·메시징: PostgreSQL 16, RabbitMQ
- 모바일: Capacitor Android

### 제외

- 다국어·다중 통화
- 반품·교환 자동화
- 개인화 추천 모델
- 실시간 상담과 소셜 기능

## 5. 기능 요구사항

| ID | 기능 | 수용 기준 |
| --- | --- | --- |
| FR-01 | 상품 탐색 | 공개 상품을 카드 목록으로 표시하고 카테고리로 필터링한다. |
| FR-02 | 검색 | 상품명과 브랜드 키워드로 검색 결과를 제공한다. |
| FR-03 | 인증 | 이메일 회원가입·로그인 후 사용자 정보와 JWT를 반환한다. |
| FR-04 | 장바구니 | 상품 추가, 수량 증감, 전체 삭제가 가능하다. |
| FR-05 | 주문 | 사용자·상품·배송 정보를 검증하고 주문 번호를 발급한다. |
| FR-06 | 결제 | 개발 환경에서는 Mock 승인 또는 Toss Payments Sandbox 승인 API를 통해 결제를 확정한다. |
| FR-07 | 재고 | 결제 승인 후 재고를 원자적으로 예약하며 부족하면 실패 이벤트를 발행한다. |
| FR-08 | 주문 확정 | 결제 승인과 재고 예약이 모두 완료되면 주문을 확정한다. |
| FR-09 | 알림 | 주문 확정·취소 이벤트를 사용자 알림으로 저장한다. |
| FR-10 | 멀티 플랫폼 | 동일한 Next.js 산출물을 웹과 Capacitor Android에서 실행한다. |

## 6. 비기능 요구사항

- 공개 웹 화면은 모바일 360px부터 데스크톱까지 반응형이어야 한다.
- 서비스는 `/health`를 제공하고 Docker healthcheck를 통과해야 한다.
- 서비스 간 DB 직접 접근을 금지하고 API 또는 RabbitMQ 이벤트를 사용한다.
- 금액은 정수 원화로 저장하고 화면에서 `ko-KR` 형식으로 표시한다.
- 주문 통합 테스트는 인증부터 주문 확정·알림 생성까지 자동 검증한다.
- 비밀값은 환경 변수로 주입하며 저장소에 커밋하지 않는다.

## 7. 성공 기준

- 신규 사용자가 3분 이내에 상품을 찾아 주문 접수까지 완료한다.
- 통합 테스트에서 모든 서비스 health와 주문 Saga가 통과한다.
- 웹 정적 빌드와 Android debug APK 빌드가 재현 가능하다.
- README만으로 로컬 실행과 아키텍처 이해가 가능하다.
